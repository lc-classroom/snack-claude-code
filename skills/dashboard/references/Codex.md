# Codex でダッシュボードを見せる

Codex（CLI・デスクトップアプリ）での基本の見せ方は、作業フォルダの `dashboard.html` とする。プレビューや公開ツールの有無は環境で異なるため、使えるものを確認する。

## 手順

1. SKILL.md の「使える材料」の HTML のひな形で、作業フォルダに `dashboard.html` を作る
   - ファイル名と置き場所は毎回同じにする（Automations で回すときも、同じ作業フォルダに書く設定にする）
   - 2回目以降は、データの部分だけを書き換える。一時ファイルに書いてから置き換え、書きかけのページを見せない
   - `dashboard.json` を正本にし、ページには JSON を埋め込む（`file://` から別ファイルの JSON を読み込む作りにしない）
2. 初回だけ、参加者が見られるようにする
   - **デスクトップアプリ**: HTML プレビューが使える場合は `dashboard.html` を開く。組み込みの Browser を使う場合も、その環境からファイルを開けるか確かめる。どちらも利用できなければ、ローカルのブラウザで開く方法を案内する
   - **CLI**: ローカルの Mac で動いていて、許可があれば `open dashboard.html` で参加者のブラウザを1回だけ開く。開けないとき（read-only など）は、絶対パスと手で開く方法を1回だけ伝える
3. 2回目以降は書き換えるだけ。通常のブラウザではページが60秒ごとに読み直す。プレビューがファイルの更新を反映しない場合は、手動で開き直す方法を初回に伝える。毎サイクル新しいタブを開いたり、チャットで報告したりしない

## チャットに書くこと

チャットに書くのは、入店、大きな作戦の変更、参加者の判断が要るとき、エラー、終了のときだけにする。それ以外の様子はダッシュボードで見せる。

## 注意

- ファイルを書いただけでは「見せられた」とは扱わない。初回に、参加者が開けたかを確かめる
- 書き込みや `open` が許されていない環境では、権限の設定を自分で変えない。できないことを参加者に伝える
- クラウド、SSH、コンテナで動いているときは、そこで `open` しても参加者の画面には出ない。その環境のパスや localhost を、参加者が見られる場所として案内しない
- ファイルを参加者が開けず、本人だけに見せる手段も無ければ、会話にテキスト版を出す。公開ホスティングや共有リンクを勝手に作らない

## 確認した仕様

2026-11-28確認。[Work with files](https://learn.chatgpt.com/docs/artifacts-viewer) と [Browser](https://learn.chatgpt.com/docs/browser) を参照。CLI にデスクトップの表示機能があるとは扱わない。HTML プレビューの自動再読み込みは保証せず、実際の表示で確認する。
