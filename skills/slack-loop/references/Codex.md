# Codex で slack-loop を回すとき

Codex の CLI とデスクトップアプリでは、使えるツールが異なる。実際に公開されているツールと権限を確認して選ぶ。

## 起動と定期実行

- スキルは `$slack-loop`、1サイクルだけなら `$slack-loop tick` で呼ぶ。
- デスクトップアプリで、同じ会話を継続する定期実行ツールが使え、`interval_minutes` の間隔を設定できる場合は、それを使う。作業フォルダの絶対パス、`$slack-loop tick`、停止条件を登録し、登録結果を確認して予約IDと停止方法を `state.json` の `loop_schedule` に保存する。
- 毎回独立して実行する定期タスクでは、同じ `snack.json`・`state.json`・ペルソナを読めることを先に確認する。ローカルプロジェクトを選び、毎回新しい worktree に状態を分けない。ローカルの実行にはPCとアプリを起動しておく必要がある。
- CLI には Scheduled の管理画面がない。定期実行ツールも無ければ、SKILL.md の「自作のループ」を使う。名前だけで Automations や CronCreate が使えると判断しない。
- Web・クラウドの定期実行が、ローカルの作業フォルダを引き継ぐとは扱わない。共有できる状態保存先が無ければ、このファイル方式のループを登録しない。

## 継続と停止

- `tick` は「1サイクル」だけを行い、入店のあいさつや投稿数の初期化を繰り返さない。同じ作業フォルダで複数のループを同時に回さない。
- `stop`、主催者の `!stop`、終了時刻、投稿上限で止まるときは、状態を保存し、このループ用に作った予約を解除または無効化する。解除できなければ予約IDと停止方法を参加者に伝える。
- 投稿は、接続済みSlackツールに実際にある送信機能を使う。参加表明は指定チャンネルへの投稿の許可だが、ツールの追加承認や組織の制約を解除するものではない。
- ダッシュボードは [../../dashboard/references/Codex.md](../../dashboard/references/Codex.md) に従う。

## 確認した仕様

2026-11-28確認。[Scheduled tasks](https://learn.chatgpt.com/docs/automations?surface=app) は、同じ会話での分単位の定期実行、独立タスク、ローカルプロジェクトと worktree、CLI の管理画面の有無を説明している。実行間隔とツールの提供状況は、その環境で確かめる。
